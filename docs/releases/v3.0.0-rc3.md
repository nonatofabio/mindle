> 🧪 **Release candidate.** Hotfix on top of rc2's PDF find feature. Beta-channel build.

## What's fixed

### Search-as-you-type no longer accumulates highlights

rc2 introduced PDF find via `PDFDocument.findString` + `view.highlightedSelections`, but setting `highlightedSelections` to a new array on each keystroke wasn't reliably evicting the previous batch — PDFKit appeared to leave the prior selection layer painted while applying the new one on top. Typing `p` → `pa` → `par` → … → `parameters` left every page covered in single-character `p` highlights from the first keystroke, with the actual `parameters` match buried in the noise.

Two coupled changes:

- **Explicit clear at the top of `performPDFSearch`** — set `highlightedSelections = nil` and `currentSelection = nil` before running any new query, so the prior render is fully evicted before the next one paints.
- **Two-character minimum** — single-char queries match basically every page anyway (every `p`, every `a`); the bar still opens on `⌘F` immediately, but no `findString` runs until you've typed at least two chars. The layer stays clean.
