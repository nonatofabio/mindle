## What's new

### Open files that live on another machine

Your notes aren't always on the laptop you're reading them on. If you work on a remote developer desktop over SSH, the Markdown you care about lives *there*, not on a mounted volume — so until now Mindle couldn't touch it.

rc5 opens remote files directly. **File ▸ Open Remote…** (`⌘⇧O`) takes an SSH target — `user@host:/path/to/notes.md` — and Mindle reads it, renders it, lets you annotate and edit it, and writes your changes back. Power users can skip the dialog: `open 'mindle://ssh/user@host/path'` from a terminal hands the file straight to Mindle, and an agent can ask for one through the MCP `open_file` tool (`open_file` now accepts `user@host:/path` as well as local paths). Remote tabs wear a small network badge, and a ↻ button re-fetches on demand.

It uses **your** SSH, not Mindle's. Mindle shells out to the `ssh`/`scp` already on your Mac, so your `~/.ssh/config` host aliases, agent keys, `known_hosts`, and ProxyJump all apply untouched — Mindle never sees a credential. Connections are non-interactive (`BatchMode`) and fail fast, so key/agent auth just works and a misconfigured host gives you a clear error instead of a hang.

Under the hood it's deliberately boring: the remote file is fetched to a local proxy and the **entire existing pipeline** — markdown-it, the editor, diff-on-reload, annotations — runs on that proxy exactly as it does for a local file. Annotations live in a local sidecar keyed to the remote target. Saves and reverts push back over SSH with an atomic temp-then-rename, so a dropped connection can never truncate the file on the far end. The local copy is always authoritative: if a push fails, your edit is safe and the error tells you so.

Closes the remote-files request.

### Notes & limits

- **Manual refresh, not live.** A remote tab doesn't poll — there's no background SSH chatter. Hit ↻ (or save) and diff-on-reload shows you anything that changed on the far end. Automatic remote watching is a possible later opt-in.
- **Annotations are local for now.** They're stored on your Mac, keyed to the remote target — a colleague opening the same remote file in their own Mindle won't see them yet. Shared, co-located remote sidecars are a separate project on the list.
- **Known rough edges (follow-ups):** a failed save-push has no one-click "retry" yet — re-saving re-pushes; and opening the *same* remote target twice in the same instant (e.g. a double-invoke) can race on the fetch. Both are narrow and never lose your local copy.
- **Tests.** The SSH target parsing and transport argument-building ship with a plain-`swiftc` assertion harness (`./run-tests.sh`) — the project builds with Command Line Tools, so this runs without Xcode.
