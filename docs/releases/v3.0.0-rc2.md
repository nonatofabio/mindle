> 🧪 **Release candidate.** Closes the three missing features from the v3.0.0-rc1 known-limitations list. Beta-channel build.

## What's new

### Find works on PDF tabs

`⌘F` on a PDF tab now opens the same Mindle search bar that's driven Markdown find since v1.5 — typing pushes the query into `PDFDocument.findString` under the hood, matches highlight on each page in PDFKit's native yellow, the active match renders darker and scrolls into view, and the bar shows `current / total` like it always has. `⌘G` / `⌘⇧G` step through matches with wrap-around. Closing the bar clears all highlights.

### Cross-page anchor disambiguation

In v3.0.0-rc1, when the same selected text appeared on multiple pages of a PDF (figure caption referenced in body, common phrase across sections), the anchor pipeline picked the first occurrence and landed on the wrong page about half the time. The anchor matcher now scores every candidate by **how much of the stored prefix matches the actual chars before** plus **how much of the stored suffix matches the actual chars after**, and picks the highest-scoring page. Empty prefix/suffix score 0 — single-match cases still work consistently — but disambiguation kicks in the moment the agent or sidecar gives the pipeline enough context.

This applies to both ends:
- **Re-anchor on reopen** — if a page has multiple occurrences of the anchor text, the right one wins now.
- **Agent-created annotations** — `create_annotation` over MCP picks the best page across the whole document, not just the first match.

### Orphaned-annotation indicator

When an annotation's anchor can't be re-resolved on reopen (page text re-extracted differently, the passage was edited away, the stored `pageIndex` is out of range), the card stays in the sidebar with its note and thread intact but its highlight no longer draws on the page. v3.0.0-rc1 gave you no way to tell from the sidebar.

Now: a small ⚠ glyph and `DRIFTED` label appear in the card header next to the author alias. Hover for the explanation. The note + thread + reactions still work fully; jump-arrow still navigates to the stored page; the highlight just doesn't paint. Markdown cards aren't affected — their anchor resolution lives in the JS pipeline at render time and a different feedback channel will handle that case if it ever needs surfacing.
