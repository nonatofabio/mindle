## What's new

### `⌘E` opens an in-place markdown editor

The recurring "can Mindle let me fix a typo without me switching to vim / iA Writer" request gets a quiet answer: **⌘E on any local markdown file** swaps the reader pane for a full-document editor. Bare raw markdown source in a monospace font. No syntax highlighting, no toolbar, no live render — Mindle isn't trying to be a markdown editor, this is the smallest surface that lets you fix a thing in-place.

Three buttons:

- **Save** writes the draft to the file on disk, closes the editor, and the reader picks up the new content via the file watcher. `⌘Return` saves from anywhere in the editor.
- **Preview** swaps the source view for a rendered Markdown preview (paragraphs, headings, lists, bold/italic, inline code, links). Click **Edit** to go back to source. Save commits from either mode.
- **Cancel** discards the draft and closes — Esc also triggers it.

Preview today uses Foundation's `AttributedString(markdown:)` for the inline render. That's enough to verify "is my formatting right" but it's lower fidelity than the reader pane proper — no syntax-highlighted code blocks, no KaTeX math, no Mermaid diagrams, no images, theme typography not exact. If a real-fidelity preview becomes the bottleneck, a v3.x follow-up can swap in a small inline `WKWebView` fed by the existing markdown-it pipeline.

### Concurrent-write protection

Mindle's file watcher reloads when something external writes to your open file — an agent, another app, a `git pull`. While you're editing, that means the in-memory `rawText` can shift under you. If you hit Save in that situation without a check, your draft would silently clobber the external change.

Drift detection: the editor captures a hash of `rawText` at open time and compares it on Save. If the file changed under you, you get a three-way dialog:

- **Save My Version** — proceed with your draft, overwriting the external change.
- **Discard My Edits** — close the editor; the reader picks up the new content the watcher already pulled in.
- **Keep Editing** — stay in the editor so you can merge the two versions by hand (copy the new content from elsewhere, edit your draft to reflect, save).

### What's in scope, what's not

**In:** local file markdown tabs (`.md`, `.markdown`, etc. on disk). The standard edit + save + cancel + drift workflow. Preview as a rough inline render.

**Out (v3.x follow-ups):**

- **URL-fetched markdown** (http(s)) and **clipboard-pasted markdown** — no writable destination, so Edit Document is disabled on those tabs. A future release could let them save to a local copy or prompt for Save-As.
- **PDF tabs** — also disabled; PDFs aren't a text-source-editable format from inside Mindle. Edit a PDF in another tool, save, Mindle's reader picks it up.
- **Receiver-side proposal cards** — when an agent or teammate proposes an edit, it flows in as a *file modification* through the existing v1.6 diff-on-reload pipeline (track-changes overlay, per-chunk ✓/✗ accept). v3.1 deliberately doesn't ship a parallel "proposal annotation" kind; the diff-on-reload path is enough.
- **Sidebar jump-arrow during edit** — clicking the arrow on an annotation card while editing currently sets `focusedAnnotation` but doesn't scroll (the reader isn't visible). For now, Save or Cancel first, then click the arrow. A v3.x polish could disable the arrow while editing, or cancel + jump.
