# Mindle v3.2.0

A navigation release, and a community one — both features come from [@ad-cqc](https://github.com/ad-cqc) (#40), who also shipped the annotation-text selection in v2.2. Small on the surface, but they change how a multi-document session feels.

## Reorder tabs by dragging

Tabs finally move. Grab one, drag it onto another to slot it in front, or drop it past the last tab to send it to the end — a thin accent line shows you where it will land. Works across every kind of tab (local, remote, PDF), and the order sticks for the session.

If you keep a reading order — spec first, notes second, scratch file last — you can now make the tab bar match the way you actually work instead of the order files happened to open.

## A heading spine on the right edge

Long documents get a quiet map. A slim column of dashes sits on the right edge of the reader — one per heading, the accent dot marking where you are. Hover and it expands into the full outline; click a heading and the reader scrolls there. Move away and it folds back to almost nothing.

It stays honest with the rest of Mindle: headings inside removed diff blocks don't appear (a track-changes deletion shouldn't navigate), the spine clears instantly on tab switch so you never see a stale outline, and it hides entirely on short documents where it would just be noise.

## Notes

- Under the hood, tab drags travel as plain text with a validated UUID payload — a custom drag type would be cleaner, but SwiftUI's drop targets on macOS never match custom item-provider UTIs. The code documents this so the next person doesn't rediscover it the hard way.
- Signed, notarized, stable channel — everyone gets it on the next update check.
