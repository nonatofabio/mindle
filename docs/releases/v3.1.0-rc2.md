## What's new

### Website refresh: hero, docs index, five reference pages

The landing at [`nonatofabio.github.io/mindle`](https://nonatofabio.github.io/mindle/) has been quietly rewritten. The dense feature grid and the shortcuts table are gone; in their place a single prose paragraph and a typographic index linking to standalone reference pages — *Reading*, *Annotations*, *Agents*, *Editor*, *Keyboard*. The new tagline is *"A quiet place to read, annotate, and think."* and the subtitle reads *"A native macOS reader for Markdown and PDF. Local, lettered, and collaborative."*

Five new docs pages cover the surface that v2.2 and v3.0 added but never surfaced — PDF reading, reactions and replies, the MCP socket and the available agent tools, the editor and drift detection, and the full keyboard reference. Reference style, no narrative. The substance lives in the doc pages so the landing can stay small.

### Bug fixes

- **Second annotation on the same paragraph sometimes landed without a highlight.** ([#32](https://github.com/nonatofabio/mindle/issues/32)) The reader built its text-position map once and reused it across annotations. After the first wrap mutated text-node values, the second annotation in the same paragraph looked up positions in a now-truncated node and silently bailed. Map is now rebuilt per iteration.
- **Sidebar file tree could shift unexpectedly when closing tabs.** ([#36](https://github.com/nonatofabio/mindle/issues/36)) The tree's `LazyVStack` re-measured rows when `store.fileURL` changed and the TabBar appeared / disappeared, nudging the scroll position. Switched to `VStack` — the directories Mindle browses are small enough that eager realization is fine.

### Enhancements

- **File → Open Recent submenu.** ([#37](https://github.com/nonatofabio/mindle/issues/37)) Standard macOS Open Recent, listing the files you've opened recently — local Markdown, local PDF, URL-fetched, clipboard. Entries pointing at files no longer on disk render disabled; **Clear Menu** at the bottom empties the list.
- **Unread dot on tabs whose file changed externally.** ([#35](https://github.com/nonatofabio/mindle/issues/35)) When several tabs are open and another agent or process writes through to an inactive tab's file or sidecar, that tab now shows a small accent-coloured dot in place of its document icon. Activating the tab clears it. A second pair of FSEvents watchers (one per inactive tab) makes this possible without touching the active-tab reload pipeline.
