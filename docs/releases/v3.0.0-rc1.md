> 🧪 **Release candidate.** First RC on the v3.0 train. Beta-channel build; flip **Mindle → Include Pre-release Updates** to pick it up. This is the largest single feature drop since v2.0 — please put it through real PDFs.

## What's new

### PDFs are first-class documents in Mindle

Open arxiv papers, exported reports, vendor PDFs — anything text-based — as tabs alongside Markdown. **Every collaboration feature you have on Markdown works on PDFs**: highlights, notes, threads, status, assign, labels, reactions, sidecar persistence, team sync via the v2.1 sidecar watcher, identity-colored overlays, agent annotations over MCP. One reading + redlining + agent surface for both content types.

Architecturally it's a parallel pipeline — native **PDFKit** (`NSViewRepresentable<PDFView>`) for rendering, the existing markdown-it pipeline untouched for `.md` and remote / clipboard tabs. `ReaderPane` picks the renderer per the active tab's extension; the two pipelines don't share view state, which keeps each one's surface small.

### What works end-to-end

**Open and read.** `File → Open…` accepts `.pdf` alongside `.md`. The file browser sidebar's tree now lists PDFs too. Drag-and-drop a PDF onto the window and it opens as a tab. `File → Open URL…` (`⌘⇧L`) accepts PDF URLs — Content-Type / magic-bytes detection caches the bytes to `~/Library/Application Support/Mindle/url-pdfs/<hash>.pdf` and renders from there. **Pinch-to-zoom and `⌘+` / `⌘-`** work via PDFView's native zoom; **`⌘0`** (or View → Fit Width) resets to fit-width after you've zoomed. Pages fill the column width by default.

**Annotate.** Select text, `⌘⇧H` highlights, `⌘⇧N` opens a note. Selections capture the passage + 32 chars of prefix/suffix on either side from `PDFPage.string`, plus the page index and a hash of the page's full text. Highlight overlay draws on the right page in your registered identity color (other authors render in theirs, agents in muted gray). Toolbar's Highlight and Note buttons now light up the moment you have a live PDF selection — the JS-only selection bridge that drove this for Markdown is mirrored on PDFs via `.PDFViewSelectionChanged`.

**Persist and re-anchor.** Closes the loop with the v2.1 sidecar: every PDF annotation writes to `.foo.pdf.mindle.json` next to the PDF, every reopen reads it back, every highlight is re-drawn on the right page. The re-anchor is robust to PDF extraction variability — first pass is a literal `range(of:)`, the fallback is a flexible-whitespace regex that treats every whitespace run as `\s+`, catching the common "column wrap dropped a newline mid-sentence" case. When `pageTextHash` matches the stored value (extraction is byte-identical to creation time), the fallback is skipped — if the literal failed under those conditions the anchor really has drifted, and the highlight is left unrendered (the annotation card stays in the sidebar with the note + jump-arrow intact).

**Collaborate.** Status pills, Resolve / Reopen, Assign dropdown, label chips, 👍 / ❤️ / 😄 reactions, threaded replies — all work on PDF annotation cards. The v2.1 sidecar watcher watches `.foo.pdf.mindle.json` automatically (it just checks `isFileURL` on the sidecar URL), so a teammate's annotation pulled in via `git pull` or shared folder lands on your screen live without close-and-reopen.

**Agent loop.** `list_open_files` returns PDF paths. `get_annotations` returns each annotation with its `pageIndex` field (and the agent-facing text render adds `Page: N`). `create_annotation` works on PDFs the same way it does for Markdown — supply `text + prefix + suffix + note`, and Mindle scans the PDF's pages for the anchor and stamps `pageIndex` + `pageTextHash` on the new annotation before adding it to the sidebar. Highlights drawn by the agent show up on the right page in muted gray. Threading, clearing, reactions, resolving, assigning — all path-keyed and content-agnostic, work without PDF-specific code.

**Export with page numbers.** `⌘⇧E` Markdown export now includes `· Page N` on annotation headings for PDF entries; JSON export carries `pageIndex` natively.

### Edge cases handled

- **Password-protected PDFs** surface a clear "Password-protected PDF" banner explaining the file needs to be unlocked in Preview first. Annotation tools stay inactive — won't let you anchor against a locked document.
- **Scanned PDFs (no OCR layer)** render normally (you can read them), but a "No extractable text" banner explains that highlights / notes can't anchor to image content.
- **Malformed PDFs** surface a "Couldn't open this PDF" banner instead of leaving the reader pane silently blank.
- **URL-fetched PDF tab titles** show the URL's last path component instead of the `<hash>.pdf` cache filename. Re-opening the same URL re-activates the existing tab.

## Known limitations for rc1

- **Cross-page anchor disambiguation.** When the same selected text appears verbatim on multiple pages, `create_annotation` (and re-anchor on reopen) picks the first match. Prefix/suffix neighborhood scoring is a v3.1 follow-up.
- **No explicit "orphaned annotation" indicator.** Annotations whose anchor doesn't re-resolve still appear in the sidebar — the jump-arrow lands on the right page, but no overlay draws. There's no visual marker yet that says "this anchor drifted."
- **PDF find-in-doc isn't integrated with Mindle's search bar.** Use the native PDFView find sheet for now.
- **No multi-author selection precision on PDFs** when the same text appears in multiple authored regions; treat as a v3.1 polish.
